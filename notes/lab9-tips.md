# Підказки до лабораторної роботи №9

## Завдання 1. Побудова топології в Packet Tracer

### Крок 1. Додайте обладнання

У нижній панелі Packet Tracer оберіть категорію **Routers** і додайте на робочу область **три маршрутизатори моделі 1841**.  
Назвіть їх **R1**, **R2**, **R3**.

Оберіть категорію **End Devices** → **PC-PT** і додайте **три комп'ютери**: **PC1**, **PC2**, **PC3**.

> ⚠️ Маршрутизатор 1841 має два інтерфейси FastEthernet (Fa0/0 і Fa0/1) та слоти для модулів.  
> Для серійних з'єднань (Se0/0/0, Se0/0/1) потрібно додати модуль **WIC-2T**:  
> клікніть на маршрутизатор → вкладка **Physical** → вимкніть живлення (кнопка на корпусі) → перетягніть модуль **WIC-2T** у **лівий слот (slot 0)** → увімкніть живлення.
>
> 💡 Якщо поставити модуль у правий слот (slot 1), інтерфейси називатимуться `Se0/1/0` і `Se0/1/1`, а не `Se0/0/0` і `Se0/0/1`, як у таблиці адресації. Команди тоді не збігатимуться зі схемою.

---

### Крок 2. З'єднайте пристрої кабелями

Використовуйте інструмент **Connections** (блискавка в нижній панелі).

| З'єднання | Тип кабелю                       | Інтерфейси                  |
| --------- | -------------------------------- | --------------------------- |
| PC1 ↔ R1  | Copper Straight-Through (прямий) | PC1 Fa0 → R1 Fa0/0          |
| PC2 ↔ R2  | Copper Straight-Through (прямий) | PC2 Fa0 → R2 Fa0/0          |
| PC3 ↔ R3  | Copper Straight-Through (прямий) | PC3 Fa0 → R3 Fa0/0          |
| R1 ↔ R2   | Copper Cross-Over (перехресний)  | R1 Fa0/1 → R2 Fa0/1         |
| R1 ↔ R3   | Serial DCE                       | **R3 Se0/0/0** → R1 Se0/0/0 |
| R2 ↔ R3   | Serial DCE                       | **R3 Se0/0/1** → R2 Se0/0/1 |

> 💡 **Серійний кабель (Serial DCE):** у Packet Tracer DCE-кінець (з іконкою годинника) отримує **перший пристрій, на який ви клікнули** після вибору кабелю.  
> За схемою лабораторної роботи DCE має бути на **R3** на обох серійних з'єднаннях, тому для обох кабелів **спочатку клікайте по R3**, а потім по R1 або R2.  
> Перевірити можна командою `show controllers serial 0/0/0` (повна форма, скорочення `Se0/0/0` тут не працює): у виводі буде рядок `DCE V.35, clock rate ...` або `DTE V.35 ...`.  
> Якщо переплутали, видаліть кабель (інструмент **Delete**) і з'єднайте заново.

## Завдання 1.1 і 2. Базове налаштування та IP-адреси

Тут об'єднано таблицю адресації (завдання 1.1) і команди початкової конфігурації маршрутизаторів (завдання 2.1-2.4), бо на практиці це робиться за один прохід.

### На маршрутизаторах (R1, R2, R3)

Клікніть на маршрутизатор → вкладка **CLI**. Перейдіть у режим конфігурації та налаштуйте кожен інтерфейс за таблицею адресації.

**Загальна послідовність команд:**

```
Router> enable
Router# configure terminal
Router(config)# no ip domain-lookup
Router(config)# hostname R1

R1(config)# interface fa0/0
R1(config-if)# ip address <IP-адреса> <маска>
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface fa0/1
R1(config-if)# ip address <IP-адреса> <маска>
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface se0/0/0
R1(config-if)# ip address <IP-адреса> <маска>
R1(config-if)# no shutdown
R1(config-if)# exit
```

> 💡 `no ip domain-lookup` (завдання 2.1) вимикає спробу знайти в DNS кожну помилково введену команду. Без неї після одруку консоль "зависає" на кілька десятків секунд. Вводьте її першою на кожному маршрутизаторі.

**Конкретні команди для R1:**

```
R1(config)# interface fa0/0
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface fa0/1
R1(config-if)# ip address 10.0.0.1 255.255.255.252
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface se0/0/0
R1(config-if)# ip address 10.0.0.9 255.255.255.252
R1(config-if)# no shutdown
R1(config-if)# exit
```

**Конкретні команди для R2:**

```
R2(config)# interface fa0/0
R2(config-if)# ip address 192.168.2.1 255.255.255.0
R2(config-if)# no shutdown
R2(config-if)# exit

R2(config)# interface fa0/1
R2(config-if)# ip address 10.0.0.2 255.255.255.252
R2(config-if)# no shutdown
R2(config-if)# exit

R2(config)# interface se0/0/1
R2(config-if)# ip address 10.0.0.6 255.255.255.252
R2(config-if)# no shutdown
R2(config-if)# exit
```

**Конкретні команди для R3:**

```
R3(config)# interface fa0/0
R3(config-if)# ip address 192.168.3.1 255.255.255.0
R3(config-if)# no shutdown
R3(config-if)# exit

R3(config)# interface se0/0/0
R3(config-if)# ip address 10.0.0.10 255.255.255.252

R3(config-if)# no shutdown

R3(config-if)# no shutdown
R3(config-if)# exit
```

> ⚠️ **Команда `clock rate 64000`** вводиться лише на DCE-кінці серійного з'єднання (у нашому випадку на R3).  
> Вона задає тактову частоту для синхронізації серійного каналу.  
> Якщо ввести її на DTE-кінці, Packet Tracer відповість `%Error: This command applies only to DCE interfaces`. Це означає, що кабель підключено "не тим кінцем": перевірте `show controllers serial 0/0/0` і за потреби перепідключіть кабель (див. крок 2).

## Завдання 3. Перевірка початкової конфігурації

### 3.1. `show ip interface brief`

Після введення всіх адрес виконайте на кожному маршрутизаторі:

```
R1# show ip interface brief
```

Очікуваний вивід для R1:

```
Interface              IP-Address      OK? Method Status                Protocol
FastEthernet0/0        192.168.1.1     YES manual up                    up
FastEthernet0/1        10.0.0.1        YES manual up                    up
Serial0/0/0            10.0.0.9        YES manual up                    up
Serial0/0/1            unassigned      YES unset  administratively down down
```

У стовпцях **Status** і **Protocol** мають бути значення `up` / `up` для всіх налаштованих інтерфейсів. Невикористаний `Serial0/0/1` на R1 (і `Serial0/0/0` на R2) залишається `administratively down`, це нормально.

| Що бачите                        | Причина                                            | Що робити                                                            |
| -------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------- |
| `administratively down` / `down` | Не введено `no shutdown`                           | Зайти в інтерфейс і ввести `no shutdown`                             |
| `down` / `down` на Serial        | Немає `clock rate` на DCE або кабель не підключено | Перевірити `clock rate` на R3, перевірити кабель                     |
| `up` / `down` на Serial          | Протилежний кінець не активовано                   | Виконати `no shutdown` на сусідньому маршрутизаторі                  |
| `up` / `down` на Fa              | Кабель не того типу або сусідній порт вимкнено     | Для R1 ↔ R2 має бути Cross-Over; на ПК перевірити, що порт увімкнено |

### 3.2. `show ip route`

```
R1# show ip route
```

До налаштування RIP кожен маршрутизатор бачить **лише свої безпосередньо підключені мережі** (позначка `C`):

```
     10.0.0.0/30 is subnetted, 2 subnets
C       10.0.0.0 is directly connected, FastEthernet0/1
C       10.0.0.8 is directly connected, Serial0/0/0
C    192.168.1.0/24 is directly connected, FastEthernet0/0
```

Якщо якоїсь мережі з трьох немає, відповідний інтерфейс не піднявся (поверніться до 3.1).

## Завдання 4. Налаштування RIP

Виконайте на **кожному** маршрутизаторі:

```
R1(config)# router rip
R1(config-router)# version 2
R1(config-router)# no auto-summary
R1(config-router)# network 192.168.1.0
R1(config-router)# network 10.0.0.0
R1(config-router)# exit
```

Для R2 і R3 замініть `192.168.1.0` на `192.168.2.0` та `192.168.3.0` відповідно. Рядок `network 10.0.0.0` однаковий на всіх трьох.

> 💡 **Чому `network 10.0.0.0`, а не `10.0.0.8`?**  
> Команда `network` приймає **класну** адресу мережі (для 10.x.x.x це клас A, тобто `10.0.0.0`). Вона означає: "увімкни RIP на всіх інтерфейсах, чиї адреси належать мережі 10.0.0.0". Якщо ввести `network 10.0.0.8`, Packet Tracer сам замінить її на `10.0.0.0`, помилки не буде.

> 💡 **`version 2` та `no auto-summary`**  
> За замовчуванням працює RIP версії 1, який не передає маски підмереж. Для нашої схеми він теж запрацює, але RIPv2 передає маски (`/30`, `/24`) і є стандартом. `no auto-summary` забороняє "склеювати" підмережі 10.0.0.0/30, 10.0.0.4/30, 10.0.0.8/30 в одну 10.0.0.0/8. Вводьте обидві команди на всіх трьох маршрутизаторах, інакше таблиці маршрутизації будуть виглядати по-різному.

> ⚠️ `network` вводиться в режимі `(config-router)`, а не `(config)`. Якщо бачите `(config)#`, спочатку введіть `router rip`.

## Завдання 5. Перевірка роботи RIP

### 5.1. Таблиця маршрутизації

Зачекайте **20-30 секунд** після налаштування останнього маршрутизатора (RIP розсилає оновлення кожні 30 с) і виконайте:

```
R1# show ip route
```

Очікуваний результат на R1 (на R2, R3 аналогічно, змінюються лише `C` та `R` рядки):

```
     10.0.0.0/30 is subnetted, 3 subnets
C       10.0.0.0 is directly connected, FastEthernet0/1
R       10.0.0.4 [120/1] via 10.0.0.2, 00:00:12, FastEthernet0/1
                 [120/1] via 10.0.0.10, 00:00:05, Serial0/0/0
C       10.0.0.8 is directly connected, Serial0/0/0
C    192.168.1.0/24 is directly connected, FastEthernet0/0
R    192.168.2.0/24 [120/1] via 10.0.0.2, 00:00:12, FastEthernet0/1
R    192.168.3.0/24 [120/1] via 10.0.0.10, 00:00:05, Serial0/0/0
```

Як читати рядок `R 192.168.2.0/24 [120/1] via 10.0.0.2`:

- `R`: маршрут отримано по RIP;
- `120`: адміністративна відстань RIP;
- `1`: метрика, кількість хопів до мережі;
- `via 10.0.0.2`: наступний маршрутизатор (next hop).

Усього на кожному маршрутизаторі має бути **6 мереж**: 3 з позначкою `C` і 3 з `R` (для мережі 10.0.0.4 на R1 два рівноцінних шляхи, це нормально).

### 5.2. Інші команди діагностики

```
R1# show ip protocols
```

Показує версію RIP, список `network`, інтерфейси, що беруть участь у RIP, і сусідів (`Gateway`). Якщо сусідів немає, перевірте `network` на сусідньому маршрутизаторі.

```
R1# show ip route rip
```

Лише маршрути з позначкою `R`. Зручно для скріншота в звіт.

```
R1# show ip rip database
```

База RIP: усі мережі, про які знає протокол, з джерелом інформації.

```
R1# debug ip rip
```

Показує в реальному часі відправлення та отримання оновлень RIP. Зачекайте одне-два оновлення (30 с), зробіть скріншот і **обов'язково вимкніть**: `undebug all` або `no debug ip rip`, інакше консоль буде засмічена.

### 5.3. Перевірка з'єднання між ПК

На PC1: **Desktop** → **Command Prompt**:

```
C:\> ping 192.168.2.10
C:\> ping 192.168.3.10
C:\> tracert 192.168.3.10
```

> 💡 Перший `ping` часто дає `Request timed out` на 1-2 пакети і потім `Reply`. Це нормально: маршрутизатори ще будують ARP-таблиці. Повторіть команду.  
> `tracert` має показати два проміжних вузли: шлюз (192.168.1.1) і інтерфейс R3 (10.0.0.10).

**Чеклист, якщо RIP-маршрутів немає або ping не проходить:**

1. `show ip interface brief` на всіх трьох: усі потрібні інтерфейси `up`/`up`?
2. `show ip protocols`: обидва `network` є на кожному маршрутизаторі? Сусіди (`Gateway`) з'явилися?
3. `version 2` і `no auto-summary` введені на **всіх** трьох (не лише на одному)?
4. На ПК правильний Default Gateway?
5. Минуло хоча б 30 с після останньої зміни конфігурації?

## Завдання 6. Збереження конфігурації

На кожному маршрутизаторі з привілейованого режиму (`#`):

```
R1# copy running-config startup-config
Destination filename [startup-config]? <Enter>
```

Коротший варіант: `R1# write`.

> ⚠️ Без збереження після перезавантаження маршрутизатора (або якщо вимкнути живлення на вкладці **Physical**) уся конфігурація зникне. Збережіть також сам файл Packet Tracer (**File → Save**, формат `.pkt`): його можна додати до звіту.
