## Що ми будуємо і навіщо

Три маршрутизатори з'єднані трикутником і обмінюються маршрутами через RIP. Мережа `192.168.3.0/24` за R3 (там стоїть Web-server) грає роль "зовнішньої" мережі: ми навмисно **не оголошуємо** її в RIP, тому R1 і R2 про неї нічого не знають.

Ідея роботи: замість того щоб розповідати всім про кожну зовнішню мережу, R3 каже сусідам "усе, чого немає у вашій таблиці, надсилайте мені". Це і є маршрут за замовчуванням.

| Етап           | Що робимо                                | Як зрозуміти, що вийшло                      |
| -------------- | ---------------------------------------- | -------------------------------------------- |
| Завдання 1     | Збираємо топологію, задаємо IP-адреси    | Усі лінки зелені                             |
| Завдання 2 і 3 | Перевіряємо конфігурацію та інтерфейси   | Потрібні інтерфейси в стані `up/up`          |
| Завдання 4     | Вмикаємо RIP                             | У таблицях з'явилися маршрути з літерою `R`  |
| Завдання 5     | Статичний маршрут за замовчуванням на R3 | На R3 з'явився запис `S*`                    |
| Завдання 6     | Роздаємо цей маршрут сусідам через RIP   | На R1 і R2 з'явився запис `R*`               |
| Завдання 7     | Перевіряємо з комп'ютерів                | З PC1 і PC2 відкривається сайт на Web-server |

## Теорія коротко

Маршрутизатор шукає мережу призначення пакета у своїй таблиці маршрутизації. Якщо відповідного запису немає, пакет відкидається.

**Маршрут за замовчуванням** (`0.0.0.0/0`) підходить під будь-яку адресу, тому спрацьовує тоді, коли точнішого маршруту в таблиці немає. Найчастіше його використовують у тупикових мережах (Stub Networks), тобто мережах з єдиним виходом назовні.

| Команда                                    | Режим              | Призначення                                                     |
| ------------------------------------------ | ------------------ | --------------------------------------------------------------- |
| `ip routing` / `no ip routing`             | `(config)#`        | Увімкнути / вимкнути маршрутизацію (увімкнена за замовчуванням) |
| `ip route 0.0.0.0 0.0.0.0 <інтерфейс\|IP>` | `(config)#`        | Створити статичний маршрут за замовчуванням                     |
| `default-information originate`            | `(config-router)#` | Роздати маршрут за замовчуванням сусідам через RIP              |
| `show ip route`                            | `#`                | Переглянути таблицю маршрутизації                               |
| `show ip interface brief`                  | `#`                | Короткий статус інтерфейсів                                     |
| `show ip protocols`                        | `#`                | Які протоколи маршрутизації працюють і з якими мережами         |
| `show running-config`                      | `#`                | Поточна конфігурація                                            |

### Як читати рядок таблиці маршрутизації

```
R*   0.0.0.0/0 [120/1] via 10.0.0.10, 00:00:08, Serial0/0/0
```

| Фрагмент        | Значення                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `R`             | Звідки маршрут: `C` (connected, підключена мережа), `S` (static, статичний), `R` (RIP)           |
| `*`             | Кандидат у маршрути за замовчуванням                                                             |
| `0.0.0.0/0`     | Мережа призначення. `0.0.0.0/0` означає "будь-яка адреса"                                        |
| `[120/1]`       | Адміністративна відстань / метрика. Для RIP відстань 120, а метрика дорівнює кількості переходів |
| `via 10.0.0.10` | Наступний перехід (next hop): адреса сусіда, якому передається пакет                             |
| `00:00:08`      | Скільки часу минуло від останнього оновлення маршруту                                            |
| `Serial0/0/0`   | Інтерфейс, через який пакет виходить                                                             |

## Шпаргалка по CLI

**Як відкрити консоль:** двічі клікніть на роутер і перейдіть на вкладку **CLI**. Якщо роутер питає про configuration dialog (`[yes/no]:`), введіть `no` і натисніть Enter.

| Запрошення               | Режим                                | Як потрапити         |
| ------------------------ | ------------------------------------ | -------------------- |
| `Router>`                | Користувацький                       | Одразу після запуску |
| `Router#`                | Привілейований                       | `enable`             |
| `Router(config)#`        | Глобальна конфігурація               | `configure terminal` |
| `Router(config-if)#`     | Налаштування інтерфейсу              | `interface <назва>`  |
| `Router(config-router)#` | Налаштування протоколу маршрутизації | `router rip`         |

Корисні дрібниці:

- Команди `show` та `ping` працюють у привілейованому режимі (`R1#`). Якщо ви в режимі конфігурації, додайте спереду `do`, наприклад `do show ip route`.
- `exit` піднімає на один рівень вище. `end` або **Ctrl+Z** одразу повертає в `R1#`.
- **Tab** доповнює команду, `?` показує доступні варіанти.
- Якщо вивід не вмістився і внизу з'явилось `--More--`: **Space** показує наступну сторінку, **Q** виходить.
- Щоб скасувати команду, введіть її ще раз зі словом `no` на початку (наприклад, `no ip address`).
- Якщо після одруківки консоль зависла на `Translating "..."...domain server`, просто зачекайте кілька секунд або натисніть **Ctrl+Shift+6**.

## Топологія мережі

```
      192.168.1.0/24         10.0.0.0/30          192.168.2.0/24
[PC1]----------------[ R1 ]----------------[ R2 ]----------------[PC2]
                Fa0/0  |   Fa0/1      Fa0/1   |  Fa0/0
               Se0/0/0 |                      | Se0/0/1
                       |                      |
           10.0.0.8/30 |                      | 10.0.0.4/30
                       |                      |
         Se0/0/0 (DCE) |                      | Se0/0/1 (DCE)
                       +--------[ R3 ]--------+
                                  | Fa0/0
                                  |
                                  | 192.168.3.0/24
                                  |
                             [Web-server]
```

> ⚠️ **R3 є DCE на обох серійних з'єднаннях.** Тому `clock rate` задається тільки на R3.

> ⚠️ **Мережа `192.168.3.0/24` не додається до RIP** на жодному роутері. На цьому побудована вся робота.

## Завдання 1. Побудова топології та базове налаштування

### Крок 1. Додайте пристрої

- 3× **Router 1841**
- 2× **PC-PT**
- 1× **Server-PT**

Перейменуйте їх як на схемі (R1, R2, R3, PC1, PC2, Web-server): клікніть на підпис під пристроєм і введіть нову назву.

### Крок 2. Встановіть серійний модуль WIC-2T

> ❗ Роутер 1841 **за замовчуванням не має серійних портів**. Без модуля при спробі підключити серійний кабель з'явиться помилка `The cable cannot be connected to that port.`

> ⚠️ Робіть цей крок **до** налаштування роутера. Вимкнення живлення стирає всю незбережену конфігурацію.

**Повторіть для кожного роутера R1, R2 і R3:**

1. Двічі клікніть на роутер і перейдіть на вкладку **Physical**
2. **Вимкніть живлення**: клікніть по вимикачу на корпусі роутера (зелений індикатор згасне)
3. Знайдіть модуль **WIC-2T** у списку зліва
4. Перетягніть його у слот з підписом **SLOT 0** (на 1841 це правий із двох великих слотів)
5. **Увімкніть живлення** тим самим вимикачем

✅ **Перевірка:** коли будете підключати кабель до роутера, у списку портів мають бути `Serial0/0/0` та `Serial0/0/1`.

> 💡 **Чому саме SLOT 0?** У SLOT 1 порти називатимуться `Serial0/1/0` і `Serial0/1/1`, а це не збігається з командами в роботі. Якщо бачите такі назви, вимкніть роутер і переставте модуль в інший слот.

> 💡 **Чому WIC-2T, а не WIC-1T?** WIC-1T має лише один порт, а роутеру R3 потрібні два серійні з'єднання.

### Крок 3. З'єднайте пристрої

Виберіть потрібний кабель у розділі **Connections** (значок блискавки), потім клікніть на перший пристрій, виберіть порт, клікніть на другий пристрій і виберіть порт.

| №   | Перший клік | Порт          | Другий клік | Порт    | Кабель            |
| --- | ----------- | ------------- | ----------- | ------- | ----------------- |
| 1   | PC1         | FastEthernet0 | R1          | Fa0/0   | Copper Cross-Over |
| 2   | PC2         | FastEthernet0 | R2          | Fa0/0   | Copper Cross-Over |
| 3   | Web-server  | FastEthernet0 | R3          | Fa0/0   | Copper Cross-Over |
| 4   | R1          | Fa0/1         | R2          | Fa0/1   | Copper Cross-Over |
| 5   | **R3**      | Se0/0/0       | R1          | Se0/0/0 | Serial DCE        |
| 6   | **R3**      | Se0/0/1       | R2          | Se0/0/1 | Serial DCE        |

> 💡 **Чому всюди Cross-Over?** Комп'ютер, сервер і роутер мають порти одного типу, тому напряму (без комутатора) вони з'єднуються перехресним кабелем. У Packet Tracer це чорна **пунктирна** лінія, саме така намальована на схемі в методичці. Прямий кабель (Straight-Through, суцільна лінія) потрібен там, де між пристроями стоїть комутатор.

> ⚠️ **Серійний кабель: порядок кліків має значення.** Виберіть **Serial DCE** (червона блискавка з годинником) і **першим клікайте на R3**. Пристрій, на який клікнули першим, стає DCE. Біля порту R3 на схемі має з'явитися маленький значок годинника.

> 💡 Поки інтерфейси роутерів не налаштовані, індикатори на лінках будуть червоні. Це нормально: порти роутера за замовчуванням вимкнені.

### Крок 5. Налаштуйте R1

Для кожного інтерфейсу робимо три речі: заходимо в нього, задаємо адресу, вмикаємо командою `no shutdown`.

```cisco
Router>enable
Router#configure terminal
Router(config)#hostname R1

R1(config)#interface FastEthernet0/0
R1(config-if)#ip address 192.168.1.1 255.255.255.0
R1(config-if)#no shutdown
R1(config-if)#exit

R1(config)#interface FastEthernet0/1
R1(config-if)#ip address 10.0.0.1 255.255.255.252
R1(config-if)#no shutdown
R1(config-if)#exit

R1(config)#interface Serial0/0/0
R1(config-if)#ip address 10.0.0.9 255.255.255.252
R1(config-if)#no shutdown
R1(config-if)#end
```

> 💡 Лінк стає зеленим лише тоді, коли інтерфейси увімкнені **з обох боків**. Тому з'єднання з R2 і R3 поки що залишаться червоними.

### Крок 6. Налаштуйте R2

```cisco
Router>enable
Router#configure terminal
Router(config)#hostname R2

R2(config)#interface FastEthernet0/0
R2(config-if)#ip address 192.168.2.1 255.255.255.0
R2(config-if)#no shutdown
R2(config-if)#exit

R2(config)#interface FastEthernet0/1
R2(config-if)#ip address 10.0.0.2 255.255.255.252
R2(config-if)#no shutdown
R2(config-if)#exit

R2(config)#interface Serial0/0/1
R2(config-if)#ip address 10.0.0.6 255.255.255.252
R2(config-if)#no shutdown
R2(config-if)#end
```

### Крок 7. Налаштуйте R3

R3 є DCE на обох серійних портах, тобто саме він задає швидкість синхронізації лінії. Тому тут додається команда `clock rate 64000`.

```cisco
Router>enable
Router#configure terminal
Router(config)#hostname R3

R3(config)#interface FastEthernet0/0
R3(config-if)#ip address 192.168.3.1 255.255.255.0
R3(config-if)#no shutdown
R3(config-if)#exit

R3(config)#interface Serial0/0/0
R3(config-if)#ip address 10.0.0.10 255.255.255.252
R3(config-if)#clock rate 64000
R3(config-if)#no shutdown
R3(config-if)#exit

R3(config)#interface Serial0/0/1
R3(config-if)#ip address 10.0.0.5 255.255.255.252
R3(config-if)#clock rate 64000
R3(config-if)#no shutdown
R3(config-if)#end
```

> ❗ Якщо на `clock rate` роутер відповів `This command applies only to DCE interfaces`, значить кабель проведено у зворотному напрямку і DCE опинився на іншому роутері. Видаліть кабель і проведіть його знову, почавши з R3 (див. Крок 3).

### Крок 8. Налаштуйте PC1, PC2 та Web-server

Тут консоль не потрібна, усе робиться через графічний інтерфейс.

1. Двічі клікніть на пристрій
2. Перейдіть на вкладку **Desktop**
3. Клікніть **IP Configuration**
4. Виберіть **Static** і заповніть поля

| Пристрій   | IP Address   | Subnet Mask   | Default Gateway |
| ---------- | ------------ | ------------- | --------------- |
| PC1        | 192.168.1.10 | 255.255.255.0 | 192.168.1.1     |
| PC2        | 192.168.2.10 | 255.255.255.0 | 192.168.2.1     |
| Web-server | 192.168.3.10 | 255.255.255.0 | 192.168.3.1     |

**Перевірте HTTP на Web-server:**

1. Двічі клікніть на **Web-server**
2. Вкладка **Services**, пункт **HTTP** у меню зліва
3. Переконайтеся, що **HTTP: On** та **HTTPS: On**

✅ **Результат завдання 1:** усі шість лінків зелені.

## Завдання 2 і 3. Перевірка налаштування

### Завдання 2. Перевірте конфігурацію

Виконайте на кожному роутері:

```cisco
R1#show running-config
```

На що дивитися у виводі:

- `hostname` правильний (R1, R2, R3)
- у кожного налаштованого інтерфейсу правильні `ip address` і маска
- під налаштованими інтерфейсами **немає** рядка `shutdown`
- на R3 під обома серійними інтерфейсами є `clock rate 64000`

### Завдання 3. Перевірте стан інтерфейсів

```cisco
R1#show ip interface brief
R2#show ip interface brief
R3#show ip interface brief
```

**Очікуваний результат на R1:**

```

FastEthernet0/0        192.168.1.1     YES manual up                    up
FastEthernet0/1        10.0.0.1        YES manual up                    up

```

**На R2:**

```
Interface              IP-Address      OK? Method Status                Protocol
FastEthernet0/0        192.168.2.1     YES manual up                    up
FastEthernet0/1        10.0.0.2        YES manual up                    up
Serial0/0/0            unassigned      YES unset  administratively down down
Serial0/0/1            10.0.0.6        YES manual up                    up
Vlan1                  unassigned      YES unset  administratively down down
```

**На R3:**

```
Interface              IP-Address      OK? Method Status                Protocol
FastEthernet0/0        192.168.3.1     YES manual up                    up
FastEthernet0/1        unassigned      YES unset  administratively down down
Serial0/0/0            10.0.0.10       YES manual up                    up
Serial0/0/1            10.0.0.5        YES manual up                    up

```

> 💡 Інтерфейси без адреси (`unassigned`) у цій роботі не використовуються, їхній стан `administratively down` є нормою.

**Що означає статус, якщо він не `up/up`:**

| Status / Protocol              | Що це означає                 | Що робити                                               |
| ------------------------------ | ----------------------------- | ------------------------------------------------------- |
| `administratively down / down` | Інтерфейс вимкнений           | Зайти в інтерфейс і виконати `no shutdown`              |
| `down / down`                  | Немає фізичного з'єднання     | Перевірити кабель, його тип і чи увімкнений порт сусіда |
| `up / down`                    | Кабель є, але лінія не працює | На серійному лінку перевірити `clock rate` на R3        |

📸 Скріншоти `show ip interface brief` з усіх трьох роутерів.

## Завдання 4. Налаштування RIP

> У методичці це завдання починається одразу з перевірки, але спочатку RIP треба увімкнути.

Що означають команди:

- `router rip` відкриває налаштування протоколу RIP
- `version 2` вмикає другу версію. Вона передає маски мереж, без цього підмережі `/30` не працюватимуть коректно
- `network <адреса>` вмикає RIP на інтерфейсах, які належать до цієї мережі, і оголошує її сусідам
- `no auto-summary` забороняє "склеювати" підмережі в одну класову мережу

> 💡 Достатньо один раз написати `network 10.0.0.0`: ця команда охоплює всі підмережі `10.0.0.x/30` на роутері.

### R1

```cisco
R1#configure terminal
R1(config)#router rip
R1(config-router)#version 2
R1(config-router)#network 192.168.1.0
R1(config-router)#network 10.0.0.0
R1(config-router)#no auto-summary
R1(config-router)#end
```

### R2

```cisco
R2#configure terminal
R2(config)#router rip
R2(config-router)#version 2
R2(config-router)#network 192.168.2.0
R2(config-router)#network 10.0.0.0
R2(config-router)#no auto-summary
R2(config-router)#end
```

### R3

> ⚠️ Мережу `192.168.3.0` тут **не додаємо**!

```cisco
R3#configure terminal
R3(config)#router rip
R3(config-router)#version 2
R3(config-router)#network 10.0.0.0
R3(config-router)#no auto-summary
R3(config-router)#end
```

### Перевірка таблиць маршрутизації

RIP надсилає оновлення раз на 30 секунд, тому маршрути з'являються не миттєво. Зачекайте пів хвилини або натисніть кнопку **Fast Forward Time** внизу вікна Packet Tracer.

```cisco
R1#show ip route
R2#show ip route
R3#show ip route
```

> 💡 У методичці написано `show ip routes`. Правильна команда: `show ip route`, без `s` у кінці.

**Які мережі кожен роутер має отримати від сусідів (записи з літерою `R`):**

| Маршрутизатор | Отримує через RIP                                 |
| ------------- | ------------------------------------------------- |
| R1            | `192.168.2.0/24`, `10.0.0.4/30`                   |
| R2            | `192.168.1.0/24`, `10.0.0.8/30`                   |
| R3            | `192.168.1.0/24`, `192.168.2.0/24`, `10.0.0.0/30` |

> 💡 У таблиці з методички для R1 вказано `192.168.1.0/24`. Це власна мережа R1, вона буде з літерою `C`. Через RIP він отримує `192.168.2.0/24`.

**Приклад очікуваного результату на R1:**

```
Gateway of last resort is not set

     10.0.0.0/30 is subnetted, 3 subnets
C       10.0.0.0 is directly connected, FastEthernet0/1
R       10.0.0.4 [120/1] via 10.0.0.2, 00:00:12, FastEthernet0/1
                 [120/1] via 10.0.0.10, 00:00:05, Serial0/0/0
C       10.0.0.8 is directly connected, Serial0/0/0
C    192.168.1.0/24 is directly connected, FastEthernet0/0
R    192.168.2.0/24 [120/1] via 10.0.0.2, 00:00:12, FastEthernet0/1
```

Зверніть увагу на дві речі:

- до мережі `10.0.0.4` є два шляхи однакової довжини (через R2 і через R3), тому в записі два рядки
- мережі `192.168.3.0/24` у таблицях R1 і R2 **немає**. Так і має бути

📸 Скріншоти `show ip route` з усіх трьох роутерів.

### Експеримент "до"

Відкрийте на **PC1** вкладку **Desktop**, потім **Command Prompt**, і виконайте:

```
ping 192.168.2.10
ping 192.168.3.10
```

- `192.168.2.10` (PC2) відповідає: RIP працює. Перший пакет може загубитися (`Request timed out`), це нормально
- `192.168.3.10` (Web-server) недоступний, відповідь буде `Reply from 192.168.1.1: Destination host unreachable`. R1 не знає, куди відправити пакет, і чесно про це повідомляє

📸 Скріншот невдалого пінгу. У кінці роботи порівняєте його з результатом "після".

## Завдання 5. Маршрут за замовчуванням на R3

```cisco
R3#configure terminal
R3(config)#ip route 0.0.0.0 0.0.0.0 FastEthernet0/0
R3(config)#end
```

Ця команда каже роутеру R3: "усі пакети, для яких немає точнішого маршруту, відправляй через інтерфейс Fa0/0".

> 💡 Після команди може з'явитися попередження `%Default route without gateway, if not a point-to-point interface, may impact performance`. Це не помилка, маршрут створено.

### Перевірка

```cisco
R3#show ip route
```

**Очікуваний результат:**

```
Gateway of last resort is 0.0.0.0 to network 0.0.0.0

     10.0.0.0/30 is subnetted, 3 subnets
R       10.0.0.0 [120/1] via 10.0.0.9, 00:00:01, Serial0/0/0
                 [120/1] via 10.0.0.6, 00:00:03, Serial0/0/1
C       10.0.0.4 is directly connected, Serial0/0/1
C       10.0.0.8 is directly connected, Serial0/0/0
R    192.168.1.0/24 [120/1] via 10.0.0.9, 00:00:01, Serial0/0/0
R    192.168.2.0/24 [120/1] via 10.0.0.6, 00:00:03, Serial0/0/1
C    192.168.3.0/24 is directly connected, FastEthernet0/0
S*   0.0.0.0/0 is directly connected, FastEthernet0/0
```

Що змінилося:

- у кінці таблиці з'явився запис `S*`: статичний маршрут (`S`), який є маршрутом за замовчуванням (`*`)
- рядок `Gateway of last resort is not set` змінився на `Gateway of last resort is 0.0.0.0 to network 0.0.0.0`

> ❗ На R1 і R2 поки що нічого не змінилося. Маршрут існує тільки на R3, сусіди про нього ще не знають.

📸 Скріншот `show ip route` на R3 із записом `S*`.

## Завдання 6. Розповсюдження маршруту через RIP

```cisco
R3#configure terminal
R3(config)#router rip
R3(config-router)#default-information originate
R3(config-router)#end
```

Команда `default-information originate` змушує R3 додавати маршрут за замовчуванням до своїх RIP-оновлень. Сусіди отримують його так само, як і звичайні маршрути.

### Перевірка на R1 та R2

Зачекайте до 30 секунд (або натисніть **Fast Forward Time**) і виконайте:

```cisco
R1#show ip route
R2#show ip route
```

**Очікуваний результат на R1:**

```
Gateway of last resort is 10.0.0.10 to network 0.0.0.0
...
R*   0.0.0.0/0 [120/1] via 10.0.0.10, 00:00:08, Serial0/0/0
```

**Очікуваний результат на R2:**

```
Gateway of last resort is 10.0.0.5 to network 0.0.0.0
...
R*   0.0.0.0/0 [120/1] via 10.0.0.5, 00:00:11, Serial0/0/1
```

`R*` означає маршрут за замовчуванням, отриманий через RIP. Адреса після `via` у кожного роутера своя: це адреса того серійного інтерфейсу R3, до якого він підключений.

📸 Скріншоти `show ip route` на R1 і R2 із записом `R*`.

### Як тепер пакет доходить до Web-server

1. PC1 відправляє пакет на `192.168.3.10` своєму шлюзу, тобто R1
2. R1 не має запису про `192.168.3.0/24`, тому використовує маршрут за замовчуванням `R*` і передає пакет на R3
3. R3 має цю мережу як підключену (`C`) і доставляє пакет серверу
4. Відповідь повертається без проблем, бо R3 знає мережу `192.168.1.0/24` через RIP

## Завдання 7. Фінальна перевірка

### 7.1 Пінг і трасування (експеримент "після")

На **PC1**: **Desktop**, потім **Command Prompt**.

```
ping 192.168.3.10
tracert 192.168.3.10
```

Пінг, який у завданні 4 не проходив, тепер має бути успішним. Команда `tracert` покаже шлях пакета:

```
  1   ...   192.168.1.1
  2   ...   10.0.0.10
  3   ...   192.168.3.10
```

Повторіть те саме з **PC2** (там шлях піде через `192.168.2.1` і `10.0.0.5`).

📸 Скріншот успішного пінгу.

### 7.2 Перевірка через браузер за IP-адресою

1. Двічі клікніть на **PC1** або **PC2**
2. **Desktop**, потім **Web Browser**
3. Введіть в адресний рядок `192.168.3.10`
4. Натисніть **Go**

✅ Якщо сторінка завантажилась, маршрутизація налаштована правильно.

### 7.3 Перевірка через google.com (як у методичці)

У методичці треба ввести `google.com`. Щоб комп'ютер зміг перетворити це ім'я на IP-адресу, потрібен DNS-сервер. Налаштуємо його на нашому Web-server.

**На Web-server:**

1. Вкладка **Services**, пункт **DNS**
2. **DNS Service: On**
3. У поле **Name** введіть `google.com`, у поле **Address** введіть `192.168.3.10`
4. Натисніть **Add**

**На PC1 і PC2:**

1. **Desktop**, потім **IP Configuration**
2. У поле **DNS Server** введіть `192.168.3.10`

Тепер відкрийте **Web Browser**, введіть `google.com` і натисніть **Go**.

✅ Якщо сайт завантажився, конфігурація пристроїв виконана правильно.

📸 Скріншот браузера з відкритою сторінкою.

### 7.4 Збереження конфігурації

На кожному роутері:

```cisco
R1#copy running-config startup-config
Destination filename [startup-config]?
```

На запитання про ім'я файлу просто натисніть **Enter**. Має з'явитися `[OK]`.

Те саме на R2 і R3. Після цього збережіть сам проєкт: **File**, потім **Save** (файл `.pkt`).

## Якщо щось не працює

| Симптом                                                          | Імовірна причина                                                                | Що робити                                                                                    |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `The cable cannot be connected to that port`                     | На роутері немає модуля WIC-2T                                                  | Завдання 1, Крок 2                                                                           |
| Серійні порти називаються `Serial0/1/0`, `Serial0/1/1`           | Модуль стоїть у SLOT 1                                                          | Вимкнути роутер, переставити модуль у SLOT 0                                                 |
| Ethernet-лінк червоний, хоча `no shutdown` виконано з обох боків | Використано прямий кабель (Straight-Through)                                    | Видалити кабель і провести Copper Cross-Over                                                 |
| Інтерфейс у стані `administratively down`                        | Не виконано `no shutdown`                                                       | Зайти в інтерфейс і виконати `no shutdown`                                                   |
| `This command applies only to DCE interfaces`                    | Серійний кабель проведено не від R3                                             | Видалити кабель і провести знову, клікнувши першим на R3                                     |
| Серійний інтерфейс `up/down` або `down/down`                     | Сусід не налаштований або немає `clock rate` на R3                              | Перевірити обидва кінці лінка та `clock rate 64000` на R3                                    |
| У `show ip route` немає записів `R`                              | RIP ще не оновився, або на одному з роутерів пропущено `version 2` чи `network` | Зачекати 30 секунд, перевірити налаштування командою `show ip protocols`                     |
| На R1 або R2 є маршрут до `192.168.3.0/24`                       | На R3 помилково додано `network 192.168.3.0`                                    | На R3: `router rip`, потім `no network 192.168.3.0`. Запис зникне з таблиць за кілька хвилин |
| На R1 і R2 немає `R*`                                            | Пропущено `default-information originate` або на R3 немає `S*`                  | Перевірити Завдання 5 і 6, зачекати 30 секунд                                                |
| Перший пакет пінгу: `Request timed out`                          | Пристрої з'ясовують MAC-адреси (ARP)                                            | Це нормально, повторити пінг                                                                 |
| Пінг до сервера проходить, а сторінка не відкривається           | На сервері вимкнено HTTP                                                        | Web-server: **Services**, **HTTP**, увімкнути                                                |
| За IP сторінка відкривається, а `google.com` ні                  | Не налаштовано DNS                                                              | Пункт 7.3                                                                                    |
| Після перезапуску роутера конфігурація зникла                    | Не збережено                                                                    | Налаштувати заново і виконати `copy running-config startup-config`                           |
